# Private publishing checklist (remove this file before going public)

- [ ] Verify no source, installer, original program binaries, licensing files, reverse-engineering details, or private build tools are included.
- [ ] Check screenshots for sensitive designs, customer information, credentials, serial numbers, private paths, and machine names.
- [ ] Review descriptions for accuracy against the screenshots and validated build.
- [ ] Decide whether to use the existing private repository `digart11/Xenetech-mod` (recommended).
- [ ] Publish only these specifically reviewed documentation assets, not the entire development folder.
- [ ] Optionally add approved general example code later, as a separate review.
- [ ] Before switching repository visibility to public, inspect **all commits/history**, not just current files.
- [ ] Review GitHub repo description, topics, and banner image.
- [ ] Do not attach an installer to Releases until distribution rights/security have been reviewed.
